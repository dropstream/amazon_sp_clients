# amazon_sp_clients

Unofficial Ruby gem for the Amazon Selling Partner API (SP-API), used
internally at Dropstream. It is one gem that wraps many generated API
clients: hand-written core code plus generated output.

## Layout

- `lib/amazon_sp_clients/` — hand-written v1 core. Edit here.
- `lib/amazon_sp_clients/v2/` — hand-written V2 core (see below), except
  `apis.rb` and `apis/`, which are generated.
- `vendor/<api_name>/` — generated v1 client per API. Committed, but never
  edit by hand. It is overwritten on every regeneration.
- `lib/generator/` — the code generator (pure Ruby + ERB, no Java).
  Not shipped with the gem. Templates live in `lib/generator/templates/`.
- `codegen-config.yml` — list of APIs to generate (name + spec path).
- `selling-partner-api-models.sha` — pinned revision of Amazon's spec
  repo (github.com/amzn/selling-partner-api-models). The generator
  clones it into `amzn-models/` (gitignored) and checks out this SHA.

## Core files (lib/amazon_sp_clients)

- `../amazon_sp_clients.rb` — entry point. Region and marketplace id
  constants, `configure`, `new_session`, feed upload/download helpers.
- `configuration.rb` — global config (credentials, region, host, sandbox,
  logger). `Configuration.default` is per-thread. The AWS IAM attrs
  (`access_key`, `secret_key`, `role_arn`, `credentials_provider`) are
  deprecated no-ops kept for consumers; removed in 2.0.
- `session.rb` — auth. Exchanges refresh token for an access token and
  gets restricted data tokens (RDT) for PII calls. `RESTRICTED_OPS`
  holds the common RDT resource lists.
- `api_client.rb` — Faraday connection used by every generated API class.
  Adds error middleware, tokens, and deserialization.
- `api_response.rb` — wraps the response into `payload` / `errors` /
  `pagination`. Payload is a Hash with symbol keys.
- `api_error.rb`, `uploader.rb` (feed upload + report download),
  `token_exchange_auth.rb` (LWA token request).
- `middlewares/raise_error.rb` — turns HTTP 4xx/5xx into Faraday errors
  and redacts auth headers from the error payload.
- `sp_*.rb` — autogenerated one-line requires that point into `vendor/`.
  Do not edit; the generator writes them.
- `marketplaces.rb` — region and marketplace tables, shared with V2.

## V2 (lib/amazon_sp_clients/v2)

`require 'amazon_sp_clients/v2'` loads V2 without v1. It shares only
`ApiResponse`, `ApiError`, `marketplaces.rb` and `adapter_loader.rb`.
Every public object must have a YARD comment (`rake yard:verify`).

- `config.rb` — frozen `Config` (Data): endpoint, sandbox, timeouts,
  user agent, optional LWA app credentials. No global.
- `client.rb` — one `Client` per merchant: the connection, `request`,
  the RDT cache, `api(klass)` factory, document helpers.
- `credentials.rb` — `Callback` (block per request) and `RefreshToken`
  (LWA, mutex, one exchange per expiry). Tokens are returned, never
  stored and read back.
- `lwa.rb`, `token.rb` — the LWA exchange and the frozen `Token`.
- `rdt.rb` — `RDT::Resource`, presets, the `Cache` (own mutex; lock order
  is cache then credentials).
- `errors.rb`, `error_mapper.rb` — the `V2::Error` tree and the
  status/exception mapping. Wrap only `ErrorMapper::TRANSPORT_ERRORS`,
  never `StandardError`.
- `documents.rb` — presigned S3 upload/download.
- `api.rb` — base class of the generated classes.

## Generated code contract

Two template sets. v1 (`vendor/`) matches the old swagger-codegen output:

- everything lives under the `AmazonSpClients` namespace,
- generated APIs take a `Session` and use `AmazonSpClients::ApiClient`,
- responses default to `AmazonSpClients::ApiResponse`,
- `auth_names` is reused to mark restricted (RDT) operations,
- only API classes and entry/require files are emitted — no models, no
  per-vendor api_client/configuration. `vendor/<name>/` holds exactly
  `lib/sp_<name>.rb` plus `lib/sp_<name>/api/*.rb`, nothing else.

V2 (`lib/amazon_sp_clients/v2/apis/<name>.rb` plus `apis.rb`):

- one class per module, `AmazonSpClients::V2::<CamelName> < V2::Api`,
  built by `client.<name>`,
- required params positional in v1 order, optional params as keywords,
  plus `rdt:`; nil keywords are left off the wire,
- every operation returns `ApiResponse`,
- `apis.rb` holds an autoload and a `Client` accessor per module.

`codegen-config.yml` lists each module's template sets (`templates:`).
The generator refuses to run while tracked files under `vendor/`,
`lib/amazon_sp_clients/sp_*.rb` or the V2 apis paths belong to no
configured module, and fails on names Ruby or the V2 signature use.

To change generated code, change the generator or its templates, run
`rake generate`, and review the diff. CI runs `rake generate:verify`,
which fails if committed output drifts from regeneration at the pin.
The V2 templates are also pinned by `spec/generator/v2_spec.rb`.

## Commands

```sh
bundle exec rspec                  # tests
bundle exec rubocop                # lint (vendor/ and sp_*.rb excluded)
bundle exec rake generate         # regenerate vendor/ at the pinned SHA
bundle exec rake generate:verify  # regenerate + fail on drift (CI)
bundle exec rake generate:update  # advance the pin + regenerate
bundle exec rake yard:verify      # every public V2 object documented (CI)
bin/console                        # irb with the gem loaded
```

Regeneration rewrites the generated files for every module in
`codegen-config.yml`. Review that diff carefully before committing;
advance the pin only in its own PR.
